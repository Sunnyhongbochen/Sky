## 2. 产品概述

### 2.1 产品定位

城市管理对象（部件）管理平台是一款面向城市管理部门的**数字化、精细化**管理工具。平台以 GIS 地理信息系统为核心底座，依托城市管理对象成果库，打通部门数据与业务壁垒，实现城市部件（市政、环卫、园林、市容、交通、公共服务等）的**可视化、分权化、协同化**管理。

### 2.2 产品目标

| 目标维度 | 描述 | 衡量指标 |
|----------|------|----------|
| **看得见** | 城市部件空间数据上图入库，GIS 图层可视化 | 部件上图率 ≥ 95% |
| **管得住** | 部门分权管理，操作可追溯 | 权限覆盖率 100%，日志审计可达 |
| **通得了** | 跨系统 API 标准化对接，消除数据孤岛 | 接口可用率 ≥ 99.9% |
| **查得准** | 移动端普查、审核、质检闭环 | 普查数据合格率 ≥ 98% |

### 2.3 产品范围

- **一期（演示版）**：实现 GIS 可视化底座、部门分权管理、标准 API 对接、普查管理核心流程。
- **二期（规划中）**：AI 智能识别部件异常、大数据分析看板、三维城市部件渲染。

### 2.4 术语定义

| 术语 | 定义 |
|------|------|
| 城市部件 | 城市公共空间内的各类市政、公用设施，如井盖、路灯、垃圾箱等 |
| 部件类别 | 部件按功能归属的分类体系，共 5 大类 17 子类 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| 普查 | 对城市部件进行现场摸底、登记、拍照、定位的周期性工作 |
| 质检 | 对普查数据质量进行审查，不合格数据退回整改 |

## 3. 用户分析

### 3.1 用户角色定义（RBAC）

| 角色 | 代号 | 职责 | 权限级别 |
|------|------|------|----------|
| **超级管理员** | super_admin | 系统全局配置、用户管理、权限分配 | 最高 |
| **部门管理员** | dept_admin | 本部门部件管理、任务配置、数据审核 | 高 |
| **普查员** | surveyor | 移动端现场采集、拍照、定位、提交 | 中 |
| **质检员** | inspector | 数据质量审查、退回整改、质检报告 | 中 |
| **普通浏览用户** | viewer | 地图浏览、空间查询、统计查看 | 低 |

### 3.2 用户画像

#### 3.2.1 超级管理员 — 张主任

- **身份**：城市管理指挥中心负责人
- **使用场景**：每日登录查看全市部件总览，分配部门权限，查看统计数据
- **痛点**：部门间数据不通，无法统一视图
- **期望**：一屏观全城，角色灵活配置

#### 3.2.2 部门管理员 — 李科长（市政科）

- **身份**：市政部门负责人
- **使用场景**：管理本部门部件台账，下发普查任务，审核上报数据
- **痛点**：传统 Excel 管理效率低，数据更新滞后
- **期望**：在线管理部件台账，一键下发任务，实时查看进度

#### 3.2.3 普查员 — 王工

- **身份**：外业采集人员
- **使用场景**：现场走动拍照、定位、填写属性、提交数据
- **痛点**：纸质表格记录易丢失，事后录入工作量大
- **期望**：手机端快速采集，离线可用，拍照自动定位

#### 3.2.4 质检员 — 赵工

- **身份**：数据质量审核人员
- **使用场景**：审查普查员提交数据，标记问题，退回整改
- **痛点**：人工审核效率低，问题跟踪困难
- **期望**：在线审核列表，快速对比，闭环跟踪

### 3.3 用户故事地图

```
        超级管理员                部门管理员              普查员               质检员
─────────────────────────────────────────────────────────────────────────────────
管理    │ 用户&权限管理           │                      │                    │
配置    │ 系统参数配置            │ 部门配置              │                    │
─────────────────────────────────────────────────────────────────────────────────
GIS     │ 全局图层总览             │ 辖区图层管理          │ 定位&采集           │ 空间查询
可视化  │ 跨部门统计             │ 本部门统计           │                    │
─────────────────────────────────────────────────────────────────────────────────
普查    │ 进度总览               │ 任务配置&下发         │ 接收任务&采集      │
管理    │                        │ 数据审核              │ 整改回复           │ 质检标记&退回
─────────────────────────────────────────────────────────────────────────────────
协同    │ API 接口管理           │ 业务对接              │                    │
对接    │                        │                      │                    │
```

## 4. 功能需求

### 4.1 GIS 可视化底座

#### 4.1.1 功能概述

基于 Leaflet.js 提供城市部件的空间数据可视化，支持二三维地图浏览、图层管理、空间查询与分析、量算工具。

#### 4.1.2 功能列表与优先级

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-GIS-01 | 空间数据上图入库 | P0 | 支持 CSV/GeoJSON/Shapefile 导入部件空间数据 |
| F-GIS-02 | 图层管理（按类别） | P0 | 按 17 种子类别切换显示/隐藏 |
| F-GIS-03 | 图层管理（按区域） | P0 | 按街道行政区划过滤 |
| F-GIS-04 | 图层管理（按责任部门） | P1 | 按归属部门过滤 |
| F-GIS-05 | 图层管理（按状态） | P1 | 按部件状态（正常/损坏/废弃）过滤 |
| F-GIS-06 | 空间查询（点选） | P0 | 点击部件查看详情弹窗 |
| F-GIS-07 | 空间查询（框选） | P1 | 矩形框选多部件列表 |
| F-GIS-08 | 空间查询（缓冲区） | P2 | 以某点为中心半径缓冲区查询 |
| F-GIS-09 | 空间统计 | P1 | 当前视野/区域部件分类汇总统计 |
| F-GIS-10 | 距离量算 | P2 | 地图上量算两点/多点距离 |
| F-GIS-11 | 面积量算 | P2 | 地图上量算多边形面积 |
| F-GIS-12 | 二维/三维可视化切换 | P2 | 2D 地图与 3D 视角切换 |

#### 4.1.3 用例描述

**UC-GIS-01：图层管理（按类别）**

| 项 | 描述 |
|------|------|
| **用例名称** | 图层管理 — 按部件类别筛选 |
| **参与者** | 所有用户 |
| **前置条件** | 用户已登录，地图已加载 |
| **主流程** | 1. 用户打开左侧图层面板<br>2. 图层面板展示 5 大类（市政/环卫/园林/市容/交通）可展开<br>3. 展开某大类后显示其子类别，每个子类带复选框<br>4. 用户勾选/取消勾选子类别<br>5. 地图上对应类别的部件实时显示/隐藏<br>6. 图层面板底栏显示当前可见部件数 |
| **后置条件** | 地图仅展示选中类别的部件 |
| **异常流程** | 全取消时显示提示"至少选择一个类别" |

**UC-GIS-02：空间查询（点选）**

| 项 | 描述 |
|------|------|
| **用例名称** | 点选查询部件详情 |
| **参与者** | 所有用户 |
| **前置条件** | 地图已加载，部件在可视范围内 |
| **主流程** | 1. 用户点击地图上的部件图标<br>2. 触发高亮效果（图标放大+边框闪烁）<br>3. 弹出信息窗（Popup），展示部件关键属性<br>4. 用户点击"查看详情"跳转至详情面板<br>5. 详情面板展示全部属性，含历史操作记录 |
| **后置条件** | 部件详情面板打开 |
| **异常流程** | 点击空白区域关闭弹窗 |

#### 4.1.4 交互规则

- **地图基础**：默认中心点北京市朝阳区（116.46°E, 39.92°N），缩放级别 13
- **底图切换**：支持 OSM/高德/Google 卫星图切换（演示版仅 OSM）
- **部件图标**：17 种子类别使用不同颜色/图标 Marker 区分
- **聚合显示**：缩小至城区级别时启用 MarkerCluster 聚合
- **响应式**：面板支持折叠/展开，移动端适配

### 4.2 部门分权管理体系

#### 4.2.1 功能概述

实现基于 RBAC 的多部门分级登录与权限管理，支持部门自主维护部件属性，全操作日志记录与历史追溯。

#### 4.2.2 功能列表与优先级

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-AUTH-01 | 用户登录/注销 | P0 | 用户名+密码登录，Session/Token 管理 |
| F-AUTH-02 | 角色管理（CRUD） | P0 | 超级管理员创建/编辑/删除角色 |
| F-AUTH-03 | 权限分配 | P0 | 为角色分配功能权限和数据范围（辖区） |
| F-AUTH-04 | 用户管理（CRUD） | P0 | 创建/编辑/禁用/删除用户，绑定角色 |
| F-AUTH-05 | 部门绑定 | P0 | 用户关联所属部门及管辖区域 |
| F-AUTH-06 | 部件属性自主维护 | P1 | 部门管理员可修改本部门部件非核心属性 |
| F-AUTH-07 | 操作日志记录 | P0 | 记录所有增删改查操作的日志 |
| F-AUTH-08 | 历史追溯 | P1 | 查看单个部件的历史变更记录 |
| F-AUTH-09 | 登录失败锁定 | P2 | 连续 5 次失败锁定 30 分钟 |
| F-AUTH-10 | 数据权限隔离 | P0 | 用户仅能看到权限范围内的部件数据 |

#### 4.2.3 用例描述

**UC-AUTH-01：部门管理员维护部件属性**

| 项 | 描述 |
|------|------|
| **用例名称** | 部门管理员维护部件属性 |
| **参与者** | 部门管理员（dept_admin） |
| **前置条件** | 用户已以 dept_admin 角色登录，部件归属用户所在部门 |
| **主流程** | 1. 用户在地图上点选部件，打开详情面板<br>2. 详情面板中"基本信息"区域显示不可编辑字段（灰色）<br>3. "维护信息"区域显示可编辑字段（白色输入框）<br>4. 用户修改属性，点击"保存"<br>5. 系统校验字段，保存成功，刷新详情<br>6. 操作日志自动追加一条记录 |
| **后置条件** | 部件属性更新，日志新增 |
| **异常流程** | 非本部门部件不显示编辑入口；必填字段为空提示 |

**UC-AUTH-02：超级管理员配置权限**

| 项 | 描述 |
|------|------|
| **用例名称** | 超级管理员配置角色权限 |
| **参与者** | 超级管理员（super_admin） |
| **前置条件** | 已以 super_admin 登录 |
| **主流程** | 1. 进入"系统管理 > 角色管理"<br>2. 点击角色行"编辑权限"按钮<br>3. 弹出权限树，按模块展示功能权限（复选框）<br>4. 勾选/取消功能权限<br>5. 设置数据权限（选择辖区街道）<br>6. 点击"保存" |
| **后置条件** | 角色权限更新，该角色下用户权限实时生效 |

### 4.3 跨系统业务对接

#### 4.3.1 功能概述

设计标准化 RESTful API 接口，为部门业务系统、GIS 平台、编码赋码系统提供数据对接能力。

#### 4.3.2 功能列表与优先级

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-API-01 | 部件查询 API | P0 | 按空间范围/类别/状态查询部件列表 |
| F-API-02 | 部件详情 API | P0 | 按部件 ID 获取完整属性 |
| F-API-03 | 部件同步 API | P1 | 第三方系统向本平台同步部件数据 |
| F-API-04 | 编码赋码对接 | P1 | 与编码赋码系统对接获取统一编码 |
| F-API-05 | GIS 服务对接 | P1 | 对接天地图/高德等外部 GIS 服务 |
| F-API-06 | API 认证鉴权 | P0 | Token/AppKey 认证机制 |
| F-API-07 | API 调用日志 | P1 | 记录 API 调用量、响应时间、异常 |
| F-API-08 | API 文档自动生成 | P2 | Swagger/OpenAPI 文档 |

#### 4.3.3 接口设计概要

详见 [7. 接口设计](#7-接口设计)。

#### 4.3.4 用例描述

**UC-API-01：第三方系统查询部件列表**

| 项 | 描述 |
|------|------|
| **用例名称** | 第三方系统通过 API 查询部件 |
| **参与者** | 已授权的第三方系统 |

| **异常流程** | Token 无效返回 401；参数非法返回 400 |

### 4.4 一站式普查管理体系

#### 4.4.1 功能概述

提供从基础数据与网格配置、任务下发、移动端采集、数据审核、质检到成果入库的全流程闭环管理。

#### 4.4.2 功能列表与优先级

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-SURVEY-01 | 基础数据配置 | P0 | 维护部件类别字典、属性模板 |
| F-SURVEY-02 | 片区网格配置 | P0 | 按街道/社区划分普查网格 |
| F-SURVEY-03 | 任务创建与配置 | P0 | 创建普查任务：绑定网格、设置时限、选择模板 |
| F-SURVEY-04 | 任务下发 | P0 | 将任务分配给普查员/普查组 |
| F-SURVEY-05 | 移动端数据采集 | P0 | 移动页面：拍照、定位、填属性、提交 |
| F-SURVEY-06 | 离线采集 | P1 | 无网络时暂存本地，有网后同步 |
| F-SURVEY-07 | 数据审核列表 | P0 | 管理员审核采集数据，通过/退回 |
| F-SURVEY-08 | 退回整改 | P0 | 退回后普查员重新编辑提交 |
| F-SURVEY-09 | 移动质检 | P1 | 质检员抽样或全量质检 |
| F-SURVEY-10 | 问题闭环跟踪 | P1 | 质检问题标记 → 整改 → 复检 → 关闭 |
| F-SURVEY-11 | 成果统一入库 | P0 | 审核通过的数据自动归档至成果库 |
| F-SURVEY-12 | 任务进度统计 | P1 | 实时查看任务完成率/通过率 |
| F-SURVEY-13 | 普查报告导出 | P2 | 按任务生成普查报告（Excel/PDF） |

| **用例名称** | 普查任务创建→采集→审核→入库 |
| **参与者** | 部门管理员 → 普查员 → 部门管理员 |
| **前置条件** | 基础数据字典已配置，网格已划分 |
| **主流程** | 1. 管理员创建任务：命名、选择网格、选择部件类别模板、设置截止日期<br>2. 管理员勾选普查员，下发任务<br>3. 普查员手机收到任务通知<br>4. 普查员到达指定网格，开始采集<br>5. 对每个部件：拍照→自动定位→选择类别→填写属性→提交<br>6. 提交后数据进入"待审核"列表<br>7. 管理员打开审核列表，逐条审查<br>8. 合格数据点击"通过"，不合格填写原因"退回"<br>9. 通过数据自动入库 |
| **后置条件** | 通过数据进入成果库，普查员可查看退回项 |
| **异常流程** | 超时未完成采集自动标记"逾期"；退回超过 3 次升级至管理员 |

**UC-SURVEY-02：质检问题闭环**

| 项 | 描述 |
|------|------|
| **用例名称** | 质检问题发现→整改→复检闭环 |
| **参与者** | 质检员 → 普查员 → 质检员 |
| **前置条件** | 部件数据已审核通过入库 |
| **主流程** | 1. 质检员从成果库抽样（或全量）检查<br>2. 发现问题，标记"质检不通过"，填写问题描述<br>3. 问题自动关联至原普查员<br>4. 普查员在"我的问题"列表中查看，现场核实<br>5. 整改后重新拍照提交<br>6. 质检员复检，确认修复后"关闭"问题<br>7. 关闭后更新成果库数据 |
| **后置条件** | 问题关闭，部件数据更新 |
| **异常流程** | 整改超时自动提醒；争议问题可升级至管理员仲裁 |
